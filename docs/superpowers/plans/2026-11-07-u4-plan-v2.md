# U4: Plan v2 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plans that follow the equipment the user picked (bodyweight-only when nothing is picked), run in 4/6/8/12-week blocks with a rotation or weekday schedule, and can be generated, started from a template and edited in place on the Plan screen.

**Architecture:** The plan stays one JSON record synced whole, so there is **no D1 migration** (`plans.data` is opaque JSON; the Worker only checks `daysPerWeek`). `PLAN.md` named `0080_plan_v2.sql`; this plan drops it. New fields are optional and read through pure accessors, so a saved plan keeps working. Block maths, schedule, edit operations and the rules plan builder are pure files with tests; the Plan screen only calls them. Equipment becomes one filter, `usableWith`, replacing `isDumbbellCompatible` everywhere.

**Tech Stack:** React 18 + TS, Vitest (node). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-06-ux-overhaul-design.md` §3.3, §4 (goal blending), §5, §8 (existing data, limits added later). Roadmap: `docs/PLAN.md` Wave 3, U4.

## Global Constraints

- Equipment: `dumbbell | kettlebell | bench | pullup_bar | band` plus the floor and the body (always implied). An exercise is offered only when **all** its equipment is owned. Nothing picked → bodyweight-only exercises (`isEquipmentFree`). barbell, cable, machine, other and unknown equipment are never offered.
- Dumbbell and kettlebell loads snap to owned weights. Band and bodyweight exercises progress on reps only (double progression, no weight step).
- Block length 4, 6, 8 or 12 weeks. Last week is a planned deload by default (toggle). Deload uses `COACH.deloadFactor` from config.
- Schedule: rotation (A → B → C → A) by default; fixed weekdays optional.
- Existing saved plan → an 8-week block (`blockOf` default). Nothing is reset silently.
- Anyone can change a template or an AI plan however they want (owner, 2026-11-06): add any library exercise, remove, reorder, change sets and rep range, swap. Limits and the avoid list still keep exercises out of **new** plans, swaps and the AI list; a limit never edits a saved plan.
- The AI suggests, the rules decide: every AI plan is validated against equipment, limits and the blend table before it is shown. No RepDB text or images go to the AI.
- All numbers live in `src/config/thresholds.ts`. Wording is training guidance, not medical advice.
- Plan changes save locally first and sync through the existing outbox (`getRepo().savePlan`).

## Review Focus

1. **Nothing fits** (no equipment picked plus tight limits, or a tiny catalogue): the builder returns an error, the screen says so in plain words, and nothing empty is saved → test in Task 4.
2. **A plan saved before U4** (no `block`, `targets`, `schedule`): opens as "Week X of 8", prescribes with the library rep range, rotates → test in Task 3 (`blockOf`, `targetOf`).
3. **Block already over** (weeks elapsed > N): shows "Block complete", never "Week 11 of 8", no deload → test in Task 3.
4. **Weekdays schedule on an unscheduled day**: next session is the next scheduled weekday, wrapping past Sunday → test in Task 3.
5. **Editing removes the last exercise of a day or an exercise with a pending weight adjustment**: the day keeps at least one exercise; the adjustment goes with the exercise → test in Task 5.
6. **AI answers w > 0 for a bodyweight exercise, or an exercise the user lacks equipment for**: w corrected to 0 and reported; the unusable exercise is rejected → test in Task 2.

  - Returns `no-exercises` when any day would be empty.

## Decisions (owner, replies on PR #27, 2026-11-07)

1. No D1 migration: the plan is stored whole as JSON.
2. Edit in place on the Plan screen only. Editing from a session's detail and the pre-workout preview moves to U5 (`docs/PLAN.md` U5 updated).
3. No standalone cardio days in U4; they move to U5 with the cardio log. U4 keeps post-lift cardio and mobility minutes as instructions.
4. Block start for an existing plan: either way is fine; `plan.updatedAt`.
5. Unweighted deload: fewer sets or fewer reps. Implemented as one set fewer (minimum 1).
6. Regenerate replaces the plan only after the user confirms the new plan is better than the current one: the preview shows the current plan next to the new one and nothing is saved until "Use this plan" is tapped.
