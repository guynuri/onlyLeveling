# U5a: Workout v2 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A workout screen you can log one-handed with no typing in the common case: focus or list view, highlighted current set, one-tap ✓ on pre-filled sets, an optional RIR tap, a pinned rest bar, a live PR badge, a preview you can edit before starting, and a finish summary.

**Architecture:** The session logic is pure and tested (`live-session.ts`, `summary`); the screen is split into small components that only render it. The in-progress session is saved on the device after every change so a killed iOS PWA does not lose a workout. Saving a finished workout is unchanged (`repo.saveWorkout`), so sync and XP keep working.

**Tech Stack:** React 18 + TS, Vitest (node). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-06-ux-overhaul-design.md` §6.4, §3.3 (timed exercises), §5 (edit in place, moved here from U4). Roadmap: `docs/PLAN.md` Wave 3, U5. **U5 is split:** this plan is U5a (workout screen); U5b (cardio log, unweighted XP, cardio streak) gets its own plan once this merges.

## Global Constraints

- 3-tap rule kept: a set the plan pre-filled is logged with one tap (✓). Typing is never needed in the common case.
- Weight steppers snap to owned weights (`Stepper values={owned}`); reps and seconds use plain steps. Touch targets 44 px, one-handed reach, no horizontal scroll, `prefers-reduced-motion` respected.
- RIR picker 0–4+, one plain line per level (UX design §6.4): 0 = "could not do another", 1 = "could do 1 more", 2 = "could do 2 more", 3 = "could do 3 more", 4+ = "plenty left". RIR is optional per set.
- Timed exercises (`mode: 'time'`): the set's `r` holds seconds; they earn no muscle XP (UX design §3.3) and no weight PR.
- The rest timer is the existing wall-clock timer (`startRest`, `remainingMs`) with its push alert (`scheduleRestAlert`); only its look changes.
- Nothing is saved as a finished workout until Finish; the in-progress session lives only on this device (not synced) and is dropped on Finish or Discard.
- All numbers in `src/config/thresholds.ts`. Suggestions stay training guidance, not medical advice.

## Review Focus

1. **The app is killed mid-workout** (iOS drops background PWAs): reopening restores the logged sets → test in Task 3.
2. **A stale draft** (from another day or another plan day) must not be restored into today's session → test in Task 3.
3. **Finish with nothing logged** is refused with a plain message; **Finish with only some exercises logged** saves only those → test in Task 2.
4. **Undo the last set** after a mis-tap, including the rest timer it started → test in Task 2.
5. **An exercise removed from the catalogue** that is still in the plan does not crash the screen → test in Task 2 (`buildLive` skips it).
6. **First session ever** (no history, no bodyweight): summary shows XP 0 gracefully and no rank-ups → test in Task 4.

### Task 2: Live session model (pure)

**Files:**
- Create: `src/domain/live-session.ts`
- Test: `src/domain/live-session.test.ts`

**Interfaces:**
- Consumes: `Prescription` (`progression.ts`), `SetRow` (`session.ts`), `Entry` (`types.ts`), `Exercise`.
- Produces:
  - `interface LiveExercise { exerciseId: string; mode: 'reps' | 'time'; prescription: Prescription; sets: SetRow[] }`
  - `buildLive(items: { exercise: Exercise | undefined; prescription: Prescription }[]): LiveExercise[]` — skips an exercise the catalogue no longer has; for `mode: 'time'` the prescription's `reps` is the target seconds.
  - `nextSetDefaults(le: LiveExercise): { w: number; r: number }` — the last logged set's weight and reps, else the prescription's.
  - `logSet(le, values: { w: number; r: number }, at: number): LiveExercise` — appends a done work set. `values` come from the steppers; the ✓ passes `nextSetDefaults`.
  - `setRir(le, setIndex: number, rir: number | undefined): LiveExercise` — 0–4 only, else unchanged.
  - `undoLastSet(le): LiveExercise`
  - `currentPosition(exs: LiveExercise[]): { exercise: number; set: number } | null` — first exercise with fewer logged work sets than prescribed; null when all are complete.
  - `toEntries(exs: LiveExercise[]): Entry[]` — exercises with at least one set, `planned` = prescription.
  - `canFinish(exs): { ok: true } | { ok: false; error: string }` — error "Log at least one set first." when no set is logged.

- [ ] **Step 1: Failing tests** (names): `buildLive skips an exercise the catalogue lacks`; `nextSetDefaults starts from the prescription, then repeats the last set`; `logSet appends a done work set with the time given`; `setRir accepts 0 to 4 and rejects 5 and -1`; `undoLastSet removes only the last set and is a no-op on an empty list`; `currentPosition walks exercise by exercise and ends with null`; `toEntries drops exercises with no sets`; `canFinish refuses an empty session` (Review Focus 3 and 4 and 5).
- [ ] **Step 2: Run** → FAIL. **Step 3: Implement.** **Step 4: Run** `npm test` → PASS.
- [ ] **Step 5: Commit** `feat(workout): pure live session model`.

### Task 4: Live PR and finish summary (pure)

**Files:**
- Create: `src/modules/xp/domain/sessionSummary.ts`
- Test: `src/modules/xp/domain/sessionSummary.test.ts`

**Interfaces:**
- Consumes: `computeProgress`/`ProgressInput` (`progress.ts`), `isNewWeightPR` (`prs.ts`), `Workout`, `Exercise`, `Group`, `Rank`.
- Produces:
  - `isLivePr(le: LiveExercise, history: HistorySession[], setIndex: number): boolean` — a weighted, reps-mode, done work set whose weight is strictly above the best in `history` (history excludes this session); false for `mode: 'time'` and for weight 0.
  - `summarize(input: ProgressInput & { workout: Workout }): SessionSummary` where `SessionSummary = { minutes: number; volumeKg: number; prExerciseIds: string[]; xpByGroup: Record<Group, number>; xpTotal: number; primary: BodySlug[]; secondary: BodySlug[]; rankUps: { group: Group; from: Rank; to: Rank }[] }`. XP and rank-ups are `computeProgress` over the history with the workout minus without it. Volume = sum of `w × r` over done work sets of reps-mode exercises. Muscles = union over exercises with a logged set (`muscles.primary` / `muscles.secondary` slugs).

- [ ] **Step 1: Failing tests:** `isLivePr is true only above the previous best`, `…false for a timed set and for weight 0`; `summarize reports minutes and volume`; `summarize lists exercises that beat their best, not the first-ever lift`; `summarize xpTotal is the difference computeProgress shows with and without the workout`; `a first session with no history has xp from the sets and no rank-ups` (Review Focus 6); `muscles hit are the union of the logged exercises`.
- [ ] **Step 2: Run** → FAIL. **Step 3: Implement.** **Step 4: Run** `npm test` → PASS.
- [ ] **Step 5: Commit** `feat(workout): live PR and finish summary`.

## Rulings made while planning (owner can overturn in the PR)

1. U5 is split in two PRs: workout screen first (this plan), cardio and XP second.
2. Timed sets log seconds in `SetRow.r`; there is no on-screen hold countdown yet (the stepper sets the seconds).
3. No rep PR for unweighted exercises (weight 0 never counts as a PR).
4. The in-progress session is kept in IndexedDB `meta`, local only, for at most 12 hours.
5. RIR is optional and asked after each ✓, never required.
